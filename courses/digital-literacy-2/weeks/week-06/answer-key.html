Instructor guide. Accept equivalent evidence-based answers. These activities evaluate demonstrated skills, not speed.

1. Name the app’s user, problem and three acceptance checks. Keep the scope to one page.

One specific user task and three observable outcomes.

2. Write a prompt naming content, behavior, accessibility and privacy boundaries.

Bounded one-file app; no personal data, secrets, payments or external dependencies.

3. Open the starter. Save a copy as resource-finder-v1.html using a plain-text editor. If working offline, no AI tool is required.

Both original and working copy retained; .html extension, not rich text or .txt.

4. Find the <h1> heading in the source and replace only its text. In the resources array, change the fictional Library Skills Desk name to Community Skills Desk. Save as resource-finder-v2.html and reopen.

Heading changes visibly; new fictional name appears and is searchable. Quotes, commas and tags stay intact.

5. Ask an approved AI tool for one small improvement, or make the heading/data edit manually. Record exactly what changed.

Revision small enough to explain; no unsupported claims about AI correctness.

6. Test blank input, matching and nonmatching search, mixed case, category filters, keyboard focus and narrow-screen layout. Record expected, actual and pass/fail.

All seven paths tested; honest failures and expected/actual evidence recorded.

7. Fix one defect or improve one requirement. Repeat its test and one previously passing test. Keep both versions.

Failed path now works or limitation clearly documented; regression check still passes.

8. Demonstrate the app. Explain HTML/CSS/JavaScript, where data lives, and why a public SaaS service needs additional design and maintenance.

HTML structure, CSS appearance, JavaScript behavior; in-page sample data, no protected backend; launch needs further checks.
