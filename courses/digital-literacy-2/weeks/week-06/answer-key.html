Week 6 · Answer and observation guide

Assess observable evidence. A spoken prompt is “With prompt”; using the quick card alone can be independent. Mark simulated work separately from hands-on performance. These observations do not change assessment scores.

Mission 6A · Specify the change

  1. One change: the search box also finds resources by category, so learning shows every Learning resource. Who: a visitor who knows the kind of help but not the name. Must stay the same (any two): capital and small letters match alike (LIBRARY finds Community library); the no-match message; keyboard use; the narrow-screen layout; only resource-finder.html changes; no outside code, personal data or sign-in. A strong spec also asks for a plan first.
  2. For example: I type learning, I expect Community library and Practice Workbook Workshop (2 fictional resources found). I type LIBRARY, I expect Community library (1 found). I type zzz, I expect No matching resources. Try a different word or reset the filters. Accept any checks a partner can run without guessing.

Review: A bounded feature with checks lets you compare the change against the request.

Mission 6B · Review the proposed change

  1. JavaScript, the rule that decides which resources match (one or two lines), and perhaps the hint text in the search box (HTML). Could break: capital-letter matching, the no-match message or the Category list. A good plan names resource-finder.html only and the matching rule. Accept any reasoned prediction; the comparison matters more than being right.
  2. Asked for: the search also looks at the category (r.category added). Not asked for but harmless: the hint now says Try library or learning. Not asked for and harmful: .toLowerCase() was removed from the line that reads the search box, so capital letters no longer match. Learners may say it in plain words: it stopped ignoring capital letters.

Review: The visual layout can remain correct while the search behavior regresses.

Mission 6C · Test, report, repair, retest

  1. Version 2 results: learning, 2 fictional resources found (Community library, Practice Workbook Workshop), pass. library, 1 found (Community library), pass. zzz, No matching resources. Try a different word or reset the filters., pass. LIBRARY and Learning, No matching resources instead of 1 and 2 found, fail (a regression: version 1 finds LIBRARY). Keyboard: Tab reaches the link, search box, Category and Reset filters, each with a thick outline, pass. Narrow screen at 400%: one column, no sideways scrolling, pass; the round Text size button can cover part of the page in every version, which is a course issue, not the agent's change.
  2. Steps: open resource-finder-agent.html and type LIBRARY. Expected: Community library (1 found), as in version 1. Actual: No matching resources; Learning also finds nothing while learning finds 2. Request: make capital and small letters match the same resources again; keep the new category search and everything else the same; show the change before applying it.
  3. LIBRARY: 1 found (Community library), pass. Learning: 2 found, pass. Passed before and still pass: learning (2 found), library (1 found), zzz (no-match message), keyboard outline. Accept the repair because the failed check now passes and no earlier check broke. If the instructor's live repair differs, it is retested the same way.

Review: Retest category search, no matches, keyboard and narrow layout so the repair does not hide a new regression.

Mission 6D · Know what “ready” means

  1. Hosted: on a web server or hosting service so anyone with the address can use it (today it is one file on the course site with fixed data). Sign-in: so each person sees only their own favorites; the server must check it, because a sign-in picture is not security. Saved data: in a database on the server, not in this page or one browser. API key: on the server only, since anyone can read a page's code with Ctrl and U. Cost and upkeep: hosting, web address, map service and AI agent fees; someone must update listings, fix problems, back up data, help users and review every agent change. Accept four of six with a reason.

Review: Private keys must stay out of downloaded browser code. Access checks also belong on the server.
