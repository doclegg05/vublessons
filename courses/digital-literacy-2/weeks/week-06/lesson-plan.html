Week 6 lesson plan: Guide an AI agent to improve a web app

Course home

Write a clear request for an AI coding agent, review what it changed, test the result, and learn what running a website as a service takes.

Learning outcomes

  • Spec: given the starter page and a one-sentence need, each learner writes a plain-English change request that names the one change, who it helps and two things that must stay the same, plus three acceptance checks in the form I do this, I expect that. A partner can run every check without asking what it means.
  • Prediction: before the agent runs, each learner writes which part of the page (HTML, CSS or JavaScript) the change needs and one thing that could break, then compares the prediction with the agent's plan and names one match or difference.
  • Review: given the before-and-after view of the agent's change (slide 10 or the projector), each learner marks every changed line as asked for or not asked for and finds the one change that breaks a requirement, with no more than one prompt.
  • Testing: at their own workstation, each learner runs the five checklist tests (happy path, no match, mixed case, keyboard, narrow screen) on the agent's version, records expected, actual and pass or fail, writes a repair request with steps, expected and actual, and after the repair reruns the failed check and two checks that passed before.
  • SaaS: using the resource finder as the example, each learner explains at least four of these six with a reason: where it would be hosted, why visitors sign in (authentication), where saved data lives, where a private API key goes, what it costs, and who maintains it.

Prepare the room

Each station: Microsoft Edge, headphones, this lesson and worksheet (typed, or printed for anyone who prefers paper), and Notepad as the plain-text editor for the optional hand repair. Learners need no account and no AI access: they open three practice pages on the course site, resource-finder.html (version 1), resource-finder-agent.html (version 2, the prepared agent result with one planted defect) and resource-finder-agent-fixed.html (version 3). At the front: your own computer on the projector with an AI coding agent signed in to your account, a practice folder holding copies of resource-finder.html and resource-finder-agent.html under version control, the terminal text enlarged, and the agent set to ask before every edit. Never show a sign-in page, key or bill on screen. Rehearse the whole demo with the class spec the week before and record it as a backup; the prepared pages are the fallback if the agent is slow, offline or does something unexpected. Print slide 10's diff and the App test log for anyone who wants paper. Play video chapters 4, 7 and 9 with captions to check sound. After your run-through, select Start fresh on this computer at each station. No paid service, purchase or learner account is required.

For unavailable features, use the course simulation or role play and label the evidence as simulated. For week 6, the instructor runs an AI coding agent on the projector; learners need no account or AI access. Supply a plain-text editor for the optional hand repair.

Lab quick card: Windows 11

Click-by-click steps for this week’s tasks in Windows 11 with Microsoft Edge. If your screen looks different, ask your instructor.

To do thisSteps
Put two pages side by sidePress Ctrl and N to open a second Edge window and open the other version there. Press the Windows logo key and the Left arrow, then choose the other window for the right side. Or hover over the Maximize button and pick a layout.
See a page's codePress Ctrl and U. The code opens in a new tab; you can read it but not change it. Close that tab when you are done.
Find a word on a page or in its codePress Ctrl and F and type the word. Matches are highlighted. Press Ctrl and G to jump to the next one.
Reload a pagePress F5, or Ctrl and R.
Test with the keyboard onlyPress Tab to move to the next control and Shift and Tab to go back. Each control should show a thick outline. On Category, press the Up or Down arrow to change the choice. On Reset filters, press Enter.
Test a narrow screenPress Ctrl and + until the zoom reaches 400%. The page should become one column you can read without scrolling sideways. Press Ctrl and 0 to go back to 100%.
Show file name extensionsIn File Explorer, select View › Show › File name extensions. Names now end in .html or .txt, so you can spot a wrong save.
Find a downloaded filePress Ctrl and J to open Downloads in Edge. Downloaded files are in the Downloads folder in File Explorer.
Open an HTML file in NotepadIn File Explorer, right-click the file, select Open with, then Notepad. If Notepad is not listed, select Choose another app.
Save a web page from NotepadChoose File › Save as. Type a name ending in .html. Set Save as type to All files, then select Save. Or type the whole name in quotation marks, such as "resource-finder-v3.html".

Using the chaptered video

Play each chapter inside its cycle, as the Show, from the video slide. Pause at the times named in the plan; the narration does not stop by itself. Ask learners to predict before a demonstration and explain the evidence afterward. Replay only the chapter needed for a refresher.

Facilitation and access

Demonstrate slowly, then let learners try. Offer keyboard and mouse paths, captions and the written transcript. Print large copies if needed. Every learner works at their own workstation; a partner coaches but does not take over. Provide extra practice time without requiring learners to disclose a disability.

Evidence to collect

  • Write a change request (a spec) for the agent in plain English. The need: visitors type a kind of help, like learning, not a name. Say the one change, who it helps, and two things that must stay the same. The slide 7 builder can make a first draft.
  • Write three acceptance checks in the form I type or press this, I expect to see that. Make one check about the new change and one about something that already works and must not break.
  • Before the agent runs, predict: which part will it change (HTML, CSS or JavaScript), about how many lines, and one thing that could break. Then read the agent's plan on the projector and write one way it matches or differs from your prediction.
  • Open slide 10 and read the agent's change (the diff). A line with a minus sign was removed; a line with a plus sign was added. Mark each changed line asked for or not asked for, and write down the change that breaks what the spec said to keep.
  • Open the agent's version (resource-finder-agent.html) at your own seat. Run the five checks in the App test log: happy path (learning, then library), no match (zzz), mixed case (LIBRARY, then Learning), keyboard only, and narrow screen (zoom to 400%). Record expected, actual and pass or fail.
  • Write a repair request the agent could act on: the steps, what you expected, what actually happened, and what must stay the same.
  • Open the repaired version (resource-finder-agent-fixed.html). Repeat the check that failed, then two checks that passed before. Record the results and say whether you accept the repair.
  • Suppose the finder became a SaaS website where many people save favorite resources. Write where it would be hosted, why visitors would sign in, where saved favorites would live, where a private API key for a map service would go, and what it would cost and who would keep it running.

Feedback and differentiation

Ask the learner to explain a choice and demonstrate the result. Mark Independent, With prompt, or Needs practice. Re-model only the missing step. For faster learners, ask them to test an edge case or explain an alternative; do not add unrelated tasks.
