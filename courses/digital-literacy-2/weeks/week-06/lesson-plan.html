Week 6 · Lesson plan

Objectives

  • Write a clear request and checks for an AI coding agent.
  • Predict what the agent will change before it starts.
  • Read the change and spot anything you did not ask for.
  • Test the result, report a problem and retest after the fix.
  • Explain what running a website as a service takes.

Observable outcomes

  • Spec: given the starter page and a one-sentence need, each learner writes a plain-English change request that names the one change, who it helps and two things that must stay the same, plus three acceptance checks in the form I do this, I expect that. A partner can run every check without asking what it means.
  • Prediction: before the agent runs, each learner writes which part of the page (HTML, CSS or JavaScript) the change needs and one thing that could break, then compares the prediction with the agent's plan and names one match or difference.
  • Review: given the before-and-after view of the agent's change (slide 10 or the projector), each learner marks every changed line as asked for or not asked for and finds the one change that breaks a requirement, with no more than one prompt.
  • Testing: at their own workstation, each learner runs the five checklist tests (happy path, no match, mixed case, keyboard, narrow screen) on the agent's version, records expected, actual and pass or fail, writes a repair request with steps, expected and actual, and after the repair reruns the failed check and two checks that passed before.
  • SaaS: using the resource finder as the example, each learner explains at least four of these six with a reason: where it would be hosted, why visitors sign in (authentication), where saved data lives, where a private API key goes, what it costs, and who maintains it.

Teaching rhythm

Tell: explain the purpose using prior experience. Show: ask for a prediction and demonstrate one step at a time. Do: learners act at their own seats using the quick card. Review: explain choices and inspect evidence. Use N for slide-specific instructor notes and the answer guide for expected results.

Pacing and recovery

Finish each essential Point B before optional extensions. Offer prepared examples, partner observation and paper annotation when tools are unavailable; record these as simulated work. Use the closing block for consolidation, not a new task.

Lab quick card: Windows 11

Put two pages side by side
Press Ctrl and N to open a second Edge window and open the other version there. Press the Windows logo key and the Left arrow, then choose the other window for the right side. Or hover over the Maximize button and pick a layout.
See a page's code
Press Ctrl and U. The code opens in a new tab; you can read it but not change it. Close that tab when you are done.
Find a word on a page or in its code
Press Ctrl and F and type the word. Matches are highlighted. Press Ctrl and G to jump to the next one.
Reload a page
Press F5, or Ctrl and R.
Test with the keyboard only
Press Tab to move to the next control and Shift and Tab to go back. Each control should show a thick outline. On Category, press the Up or Down arrow to change the choice. On Reset filters, press Enter.
Test a narrow screen
Press Ctrl and + until the zoom reaches 400%. The page should become one column you can read without scrolling sideways. Press Ctrl and 0 to go back to 100%.
Show file name extensions
In File Explorer, select View › Show › File name extensions. Names now end in .html or .txt, so you can spot a wrong save.
Find a downloaded file
Press Ctrl and J to open Downloads in Edge. Downloaded files are in the Downloads folder in File Explorer.
Open an HTML file in Notepad
In File Explorer, right-click the file, select Open with, then Notepad. If Notepad is not listed, select Choose another app.
Save a web page from Notepad
Choose File › Save as. Type a name ending in .html. Set Save as type to All files, then select Save. Or type the whole name in quotation marks, such as "resource-finder-v3.html".
